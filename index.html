node:philosophy

How I think about engineering

[DRAFT — these are editable starter notes in your voice. Replace with your own words.]

What makes good software

Software that's easy to change. Clever code impresses once; readable code pays out every time someone else opens the file.

How I debug

Reproduce first, theorise second. The bug is almost never where the stack trace points — it's where an assumption quietly broke.

Speed vs. quality

Ship fast where it's cheap to be wrong; slow down where it's expensive to be wrong. The skill is telling the two apart.

What production taught me

Every system is only as good as its worst on-call night. Observability and clean rollbacks aren't extras — they're the feature.
